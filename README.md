## Что получает менеджер

Карточку на один экран:

- что покупают, сколько и к какому сроку — по техническому заданию, а не по заголовку закупки;
- что за заказчик: выручка, прибыль и капитал за последний опубликованный год по отчётности ФНС;
- кому звонить: имя, роль и телефон;
- с чего начать разговор и какие вопросы задать по документам;
- кнопки «В работу» и «Мимо».

В Telegram приходят только карточки с проверенным телефоном. Оценка A означает, что найден конкретный человек с рабочим номером, B — телефон отдела или приёмной. Контакт из стороннего справочника получает отдельную пометку и оценку не выше B. Закупка без телефона остаётся в журнале исследования.

Последнее нажатие кнопки задаёт статус лида, его можно исправить. Ответ на карточку сохраняется как заметка. В меню бота две выгрузки Excel, и заметки попадают в обе:

- «Выгрузить новые лиды» — доставленные карточки без решения менеджера;
- «Выгрузить в работе» — лиды с последним решением «В работу».

Таблицы собираются в момент запроса, поэтому ручные правки в скачанном файле при следующей выгрузке не сохраняются. Подписка включается командой `/digest_on` и выключается `/digest_off`.

Карточки приходят по будням в 09:00, 12:00 и 15:00 по Москве. Источник и исследователь работают каждый день, найденное за выходные ждёт понедельника. Если приём предложений закончился до отправки, карточка остаётся в журнале. После пустого слота приходит короткий статус, чтобы отсутствие лидов нельзя было спутать со сбоем.

## Как это работает

Закупку разбирает агент-исследователь. Он получает карточку закупки, документы и инструменты для чтения и поиска, а дальше сам решает, какие файлы и страницы открыть, когда искать дальше и когда остановиться. Контакт он ищет сначала в закупке и документах, затем на сайте заказчика и в открытых источниках. Какие закупки подходят, что выяснять о заказчике и о чём говорить при звонке, записано в инструкции агента, а не в ветках кода.

Код берёт на себя то, где нужна гарантия, а не суждение:

- каждые 30 минут забирает новые закупки и документы и запечатывает снимок данных для исследования;
- ограничивает исследование по числу шагов и по деньгам;
- [`grounding.py`](agent_radar/lead_agent/grounding.py) сверяет телефон, имя и почту с текстами, которые агент действительно прочитал. Значение, которого там нет, удаляется, оценка пересчитывается. Телефон сверяется по десяти цифрам номера без учёта записи, имя — без учёта падежных окончаний. Это механическая проверка: она отсекает номера, которые модель придумала, но не доказывает, что цифры в источнике были именно телефоном этого человека. Актуальность номера и контакт выясняются при звонке;
- ведёт журнал, доставляет карточки и сообщает администратору о задержке источника, сбое исследования, зависшей отправке и закупках в карантине.

По умолчанию исследование ведёт Qwen 3.7 Flash. Если результат ниже A, закупку ещё раз исследует DeepSeek v4.1 Flash.

Версия закупки определяется по данным, которые видит агент: карточке, заказчику, статусу, датам и текстам документов. Уже исследованная версия повторно не разбирается. Изменённая закупка проходит исследование заново, а повторная карточка помечается как обновление и не отправляется в чат, где по этой закупке последним решением было «Мимо».

```text
Bidzaar API -> источник (каждые 30 минут) -> документы
    -> analysis-source.json + запечатанный снимок
    -> исследователь (07:30, 10:30, 13:30 МСК)
    -> проверка контактов -> журнал leads.sqlite3
    -> Telegram (будни 09:00, 12:00, 15:00 МСК)
        -> «В работу» / «Мимо», заметки ответом, две выгрузки Excel

Запечатанный снимок -> ответы бота на свободные вопросы
                       через инструменты только для чтения
Состояние источника, исследования и доставки -> сообщения администратору
```

## Агент вместо цепочки кода

Первая версия радара была пакетной цепочкой: программа делила документы на части и проводила их через модель по заранее заданным шагам. Каждый новый случай требовал ещё одной ветки в коде.

На одном наборе из 16 закупок цепочка нашла человека с проверенным телефоном в 3 случаях. Агент-исследователь на том же наборе нашёл его в 8 или 9 случаях, в зависимости от модели. Это результат одного прогона рабочей системы, записанный в её документации. Сам набор в публичный репозиторий не входит: публичные тесты проверяют поведение кода на синтетических данных.

## Запуск проверок

Python 3.12, PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.lock -r requirements-dev.txt
python -m pip check
$env:PYTHONUTF8='1'
python tools/check_public_boundary.py
python -m compileall -q app agent_radar scripts tests tools
python -m unittest discover -s tests -p "test_agent_radar_*.py"
python -m unittest discover
python scripts/apply_migrations.py --dry-run
```

В Linux окружение активируется командой `source .venv/bin/activate`. Тесты не вызывают модель и не обращаются к живым источникам. Проверки прав POSIX, некоторые символьные ссылки и Linux-публикация каталогов на Windows пропускаются. Фактические результаты записаны в [протоколе проверки](docs/VERIFICATION.md).

Для собственного исследования нужны пакет `analysis-source.json` с карточками и текстами документов, ключ провайдера модели и промпт, настроенный оператором. Формат пакета показан в [документации исследователя](agent_radar/lead_agent/README.md). Веб-поиск использует необязательный пакет `ddgs`; без него инструмент прямо сообщает, что поиск недоступен. Telegram подключается к уже существующему приложению через переданный адаптер, отдельный поллер меню не создаётся. Получателей задаёт оператор списком разрешённых пользователей и подписками.

## Ограничения

- Документы читаются в форматах PDF, DOCX, DOC, XLSX, TXT, ZIP и 7z. OCR, RAR и XLS не поддерживаются; недоступный или нечитаемый файл отмечается как пробел в данных, и агент это учитывает.
- Для DOC нужен `antiword`, для 7z — внешний `7zz` или `7z`. Недоверенные документы нужно обрабатывать в отдельном процессе без сети и с лимитами ресурсов.
- Источник хранит ограниченное окно изменений, поэтому это не полный реестр активных процедур площадки.
- Система сама не звонит и не пишет заказчикам. Контакт и следующий шаг проверяет менеджер.
