# AI Tender Radar

[![CI](https://github.com/pavel-logachev/ai-tender-radar/actions/workflows/quality.yml/badge.svg)](https://github.com/pavel-logachev/ai-tender-radar/actions/workflows/quality.yml)
[![Python 3.12](https://img.shields.io/badge/Python-3.12-2f3e73)](https://www.python.org/)
[![Tests 726](https://img.shields.io/badge/tests-726-167c69)](docs/VERIFICATION.md)
[![License AGPL-3.0](https://img.shields.io/badge/license-AGPL--3.0-6b5fd6)](LICENSE)

AI Tender Radar находит закупки серверов и систем хранения данных на Bidzaar и готовит менеджеру короткую карточку: кому звонить и о чём говорить. Закупка даёт повод познакомиться с заказчиком и обсудить его потребность в оборудовании.

Агент-исследователь читает закупку и документы, смотрит бухгалтерскую отчётность заказчика в ФНС. Контакт с телефоном он ищет сначала в процедуре, затем на сайте заказчика и в открытых источниках. В карточке остаются предмет закупки, сроки, сведения о заказчике и темы для первого разговора.

[Статья о проекте и переходе к исследовательскому агенту](https://logachev.net/journal/ii-agent-dlya-generacii-lidov-zakupki/).

## Как менеджер работает с результатом

В Telegram приходят только карточки с проверенным телефоном. Оценка A означает, что найден названный человек с рабочим номером; B означает телефон отдела или приёмной. Контакт из стороннего справочника получает отдельную пометку и оценку не выше B. Результат без телефона остаётся в журнале исследования.

Под карточкой есть кнопки «В работу» и «Мимо». Последнее нажатие задаёт статус; его можно исправить. Ответ на карточку сохраняется как заметка и попадает в обе выгрузки Excel:

- «Выгрузить новые лиды»: доставленные карточки без решения менеджера.
- «Выгрузить в работе»: лиды с последним решением «В работу».

Таблицы собираются при запросе. Правки, внесённые вручную в скачанный Excel, при следующей выгрузке не сохраняются. Подписка управляется командами `/digest_on` и `/digest_off`.

Рабочее расписание доставки: понедельник-пятница, 09:00, 12:00 и 15:00 МСК. Источник и исследователь работают каждый день; найденное за выходные ждёт понедельника. Если приём предложений завершился до отправки, карточка остаётся в журнале. Проверка здоровья сообщает администратору о задержке источника, сбое исследования, зависшей отправке и закупках в карантине. После пустого слота приходит короткий статус, чтобы отсутствие лидов можно было отличить от сбоя.

## Поток

```text
Bidzaar API -> источник (каждые 30 минут) -> документы
    -> analysis-source.json + запечатанный снимок
    -> исследователь (07:30, 10:30, 13:30 МСК)
    -> проверка контактов -> журнал leads.sqlite3
    -> Telegram (будни 09:00, 12:00, 15:00 МСК)
        -> «В работу» / «Мимо», заметки ответом, две выгрузки Excel

Запечатанный снимок -> ответы бота на свободные вопросы
                       через инструменты только для чтения
Состояние источника, исследования и доставки -> сообщения администратору
```

Схема описывает рабочую систему. В публичном репозитории есть исследовательское ядро и код Telegram/Excel; боевой промпт, коннектор площадки и развёртывание остаются закрытыми. Вместо боевого промпта опубликован [универсальный пример](agent_radar/lead_agent/prompt.md). Полная [граница публикации](docs/PUBLICATION_BOUNDARY.md) также исключает реальные закупки, контакты, рабочие базы и секреты. В текущем дереве тестовые идентификаторы закупок и документов, заказчики, суммы и контакты обезличены; реальные домены оставлены только в проверках формата URL и разрешённых хостов. Это не утверждение об уже опубликованной истории Git: [её ограничения](docs/VERIFICATION.md#ранее-опубликованная-история) описаны отдельно.

## Где принимаются решения

Промпт задаёт профиль закупки, порядок исследования, оценку заказчика и содержание разговора. Агент выбирает, какие документы и страницы прочитать, когда продолжить поиск и когда закончить. В рабочем контуре используется Qwen 3.7 Flash; результат ниже A получает второе исследование DeepSeek v4.1 Flash.

Код собирает данные и документы, ограничивает объём работы, проверяет результат и хранит состояние. [`grounding.py`](agent_radar/lead_agent/grounding.py) сопоставляет телефон, имя и почту с тем, что агент действительно прочитал, удаляет неподтверждённые значения и пересчитывает оценку. Для телефона допускаются различия в форматировании, для имени учитываются окончания. Такая проверка подтверждает наличие контакта в источнике, но не его актуальность или принадлежность нужному человеку.

Версия закупки считается по доступным агенту данным: карточке, заказчику, статусу, датам и текстам документов. Сохранённая версия повторно не исследуется. Изменённая закупка проходит исследование заново; повторная карточка помечается как обновление и не отправляется в чат, где последнее решение по закупке было «Мимо».

## Проверка подхода

На одном наборе из 16 закупок исследование выполнили двумя моделями. В зависимости от модели человек с проверенным телефоном нашёлся в 8-9 из 16 случаев; прежний код находил его в 3 из 16. Это результат конкретного прогона рабочей системы, записанный в исходной документации. В репозитории нет этого набора; публичные тесты проверяют поведение кода на синтетических данных.

## Запуск проверок

Python 3.12, PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.lock -r requirements-dev.txt
python -m pip check
$env:PYTHONUTF8='1'
python tools/check_public_boundary.py
python -m compileall -q app agent_radar scripts tests tools
python -m unittest discover -s tests -p "test_agent_radar_*.py"
python -m unittest discover
python scripts/apply_migrations.py --dry-run
```

В Linux окружение активируется командой `source .venv/bin/activate`. Тесты не вызывают модель и не обращаются к живым источникам. Проверки прав POSIX, некоторые символьные ссылки и Linux-публикация каталогов пропускаются на Windows. Фактические результаты записаны в [протоколе проверки](docs/VERIFICATION.md).

Для собственного исследования нужен пакет `analysis-source.json` с карточками и текстами документов, ключ провайдера модели и настроенный оператором промпт. Формат пакета показан в [документации исследователя](agent_radar/lead_agent/README.md). Веб-поиск использует необязательный пакет `ddgs`; без него инструмент возвращает явное сообщение о недоступности поиска. Telegram подключается к уже существующему приложению через переданный адаптер, отдельный поллер меню не создаёт. Получателей задаёт оператор через список разрешённых пользователей и подписки.

## Ограничения

Документы поддерживаются в PDF, DOCX, DOC, XLSX, TXT, ZIP и 7z. OCR, RAR и XLS не поддерживаются; недоступный или нечитаемый файл отмечается как пробел. Для DOC нужен `antiword`, для 7z нужен внешний `7zz` или `7z`. Обработчик недоверенных документов требует отдельного процесса без сети с лимитами ресурсов. Источник хранит ограниченное окно изменений, поэтому это не полный реестр активных процедур площадки. Система сама не звонит и не пишет заказчикам: контакт и следующий шаг проверяет менеджер.
