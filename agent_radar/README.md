# Исследовательское ядро Tender Radar

Текущий рабочий поток описан в [главном README](../README.md). Этот каталог содержит публикуемую часть исследователя, проверку контактов и рабочий процесс менеджера. Коннектор площадки, рабочий промпт и развёртывание остаются закрытыми по [границе публикации](../docs/PUBLICATION_BOUNDARY.md).

```text
Карточка и тексты документов -> lead_agent.runner -> агент
    -> grounding -> leads.sqlite3 -> Telegram-карточка
        -> feedback / заметки -> Excel «новые» и «в работе»
Состояние источника и исследования, журнал доставки -> health
Снимок + manifest + commit -> bundle -> SnapshotStore
```

## Модули

- `lead_agent/`: цикл агента, инструменты, проверка, журнал и доставка. [Контракт входного пакета и запуска](lead_agent/README.md).
- `telegram_menu.py`, `subscriptions.py`: подписки и обработчики менеджера в существующем Telegram-приложении. Публичный вариант принимает адаптер вызывающей стороны; конфигурацию шлюза он не содержит.
- `document_extract.py`, `document_package.py`: ограниченное извлечение текста. Обработку недоверенных файлов запускают без сети и с лимитами ресурсов.
- `hardware_profile.py`: широкий предварительный фильтр серверов и СХД без ценового порога.
- `snapshot.py`, `bundle.py`, `state_files.py`: чтение запечатанного снимка, проверка хешей, атомарные записи и блокировка одного писателя.

`RADAR_DIGEST_STATE_ROOT` и имя `digests.sqlite3` сохранены для совместимости; в этой базе только подписки. Старого digest/review-queue потока в пакете нет.

## Проверка

```powershell
$env:PYTHONUTF8='1'
python -m unittest discover -s tests -p "test_agent_radar_*.py"
```

Тесты используют синтетические карточки и заглушки сети и модели. Linux-права и публикация каталогов отдельно проверяются в CI. Первое поколение `app/` к этому пакету не относится.
