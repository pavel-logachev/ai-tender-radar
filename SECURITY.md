# Политика безопасности

Исправления безопасности вносятся в текущую ветку `main`.

## Сообщения об уязвимостях

Обход контроля доступа, SSRF, ошибки разбора документов, prompt-инъекции и раскрытие данных сообщайте приватно через GitHub Security Advisories этого репозитория. Не создавайте публичный issue с рабочими данными.

Укажите затронутый компонент и минимальное воспроизведение на синтетических данных, ожидаемое поведение и последствия. Не прикладывайте действующие токены, клиентские записи или закупочные документы.

## Ответственность оператора

- Подключать только источники, к которым есть право доступа, и ограничивать исходящий трафик.
- Изолировать обработку документов без сети с лимитами ресурсов.
- Авторизовать Telegram-обновления до передачи обработчикам, задавать список разрешённых пользователей и защищать локальные SQLite-журналы. На Windows нужны ACL; проверка POSIX-прав их не заменяет.
- Защищать пакеты исследования, вывод инструментов и модели, карточки, заметки и выгрузки как деловые данные.
- Проверять контакт и содержание карточки до обращения к заказчику. Grounding устанавливает наличие контакта в прочитанном тексте, не его актуальность или принадлежность.

Публичное дерево содержит только синтетические данные. Рабочий промпт, коннектор и развёртывание остаются закрытыми по [границе публикации](docs/PUBLICATION_BOUNDARY.md). PostgreSQL и миграции относятся к сохранённому первому поколению.
