# Архитектура

## Рабочий поток

Источник Bidzaar выбирает закупки серверов и СХД широким предварительным фильтром. Цена закупки не задаёт порог допуска. Источник обновляется каждые 30 минут и накапливает профильные изменения за 14 дней. Неразбираемая закупка попадает в карантин, остальные продолжают обработку.

После ограниченного скачивания и извлечения текста публикуются два представления: запечатанный снимок для вопросов боту и `analysis-source.json` для исследователя. Исследователь читает закупку и документы, проверяет экономику заказчика в ФНС, ищет опубликованный рабочий телефон и готовит карточку. Правила суждения задаёт промпт.

```text
Источник -> документы -> пакет исследователя -> агент -> grounding
    -> leads.sqlite3 -> delivery -> Telegram -> feedback / comments / Excel
               состояние этапов -> health -> администратор
Снимок -> инструменты только для чтения -> ответы бота по закупкам
```

Коннектор площадки, оркестрация источника и документов, боевой промпт и конфигурация развёртывания находятся за [границей публикации](PUBLICATION_BOUNDARY.md). Ниже описаны опубликованные контракты.

## Исследование

`lead_agent/agent.py` реализует цикл с OpenAI-совместимым API, инструментами и бюджетами шагов и расходов. `tools.py` предоставляет чтение процедуры и документов, веб-поиск, чтение страницы или PDF и отчётность ФНС. Каждый переход по редиректу проверяется на непубличные адреса; веб-вывод помечается как недоверенные данные. Поиск `ddgs` необязателен и сообщает о своей недоступности явно.

`runner.py` выбирает новые активные версии, начиная со срочных. Версия (`store.version`) зависит от того, что агент может прочитать; служебные обновления источника не создают новую версию. Документы, ожидающие загрузки, откладывают исследование, если до конца приёма больше 24 часов. При результате ниже A запускается резервная модель. Неразбираемый результат повторяется один раз, затем сохраняется как `failed`.

`grounding.py` удаляет телефон, имя и почту, не найденные в выводе инструментов. Телефон сравнивается по цифрам, имя по частям с допустимыми окончаниями; почта сравнивается буквально без учёта регистра. Проверка не устанавливает связь между человеком и номером и не подтверждает финансовые выводы. Оценка пересчитывается: A для названного человека с телефоном, B для телефона без имени или контакта низкой уверенности, C при отсутствии телефона. Профильный `candidate` с проверенным телефоном становится `lead`.

## Данные и доставка

`LeadStore` ведёт SQLite-журнал исследований, попыток, отправок, решений и заметок. Уникальность задаётся парой закупка/версия. Каталог и файлы защищаются локальными проверками путей; POSIX-права не заменяют ACL Windows.

Доставка резервирует запись до отправки. Неоднозначный исход записывается как `uncertain` и автоматически не повторяется. При 429 резервирование освобождается, отправка в этот чат останавливается. Истёкшая закупка не отправляется. Новая версия получает пометку об обновлении и учитывает последнее «Мимо» в конкретном чате. Будние слоты 09:00, 12:00 и 15:00 МСК задаются внешним планировщиком; ручной вызов `delivery` сам календарь не ограничивает.

`Subscriptions` пересекает включённые подписки со списком разрешённых пользователей. `telegram_menu.py` регистрирует обработчики в приложении вызывающей стороны через переносимый адаптер. Кнопки дают последнее решение менеджера; заметки принимаются только ответом на подтверждённо доставленную карточку своего чата. Обе выгрузки формируются заново из журнала. `export.py` создаёт XLSX без исполняемых формул, макросов и вложений.

`health.py` читает контрольные точки источника и исследования, карантин и журнал отправки. Проблема сообщает о себе при появлении, повторяется через сутки и закрывается сообщением о восстановлении. Режим `--slot` добавляет тихий статус после пустой доставки.

## Снимок и документы

`SnapshotStore` ограничивает снимок 500 карточками и 2 МБ, привязывает чтение документов к хешу снимка. `bundle.py` проверяет контрольные суммы снимка, манифеста и записи публикации при каждом чтении. Они подтверждают неизменность байтов, подписью источника не являются. Публикация каталога не заменяет существующий путь; функция чтения не получает сетевые учётные данные.

`document_extract.py` и `document_package.py` работают с ограниченными байтами, не выполняют макросы и формулы, не раскрывают вложенные архивы. Ошибка извлечения означает пробел. Для недоверенных документов нужен процесс без сети с ограничениями памяти, процессора и времени. `state_files.py` даёт атомарную запись и неблокирующую блокировку одного писателя.

## Первое поколение

`app/` и PostgreSQL-схема сохранены для истории и собственных тестов. Этот пакетный конвейер остановлен и не входит в исследовательский поток.
